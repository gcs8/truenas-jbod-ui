CORE controller device lists: a `show devices` row whose speed mprutil prints as `Unk` or `???` is now read with its own enclosure handle and slot instead of taking them from the columns after it, so the device is counted in its own enclosure. Under mprutil's heading a row must end with exactly its speed, enclosure handle, slot and width columns; a row missing one of them (even when a four-digit slot looks like an enclosure handle) now leaves the device list not read whole and withholds the enclosure's device count, instead of placing the device under another enclosure handle. A numeric speed is read in any form read before (any digits with an optional fraction, such as `100` or `012.0`), and a row whose enclosure handle is not four hex digits is not understood. Bare rows printed without the heading must still carry a numeric speed, so one with `Unk`, `???` or no speed column is not understood; a bare row without a width whose speed is a four-digit whole number, which reads equally as a row missing its speed, is now refused instead of read.
