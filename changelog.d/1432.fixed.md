Restore: an import now binds the installed history to the validated member's size and SHA-256 between validation and activation, and ignores or refuses SQLite side files. Validation records the size and SHA-256 of the member it judged, read as a single file; activation copies the staged member through one opened file into a private copy and refuses the import unless that copy has the validated size and SHA-256. SQLite reads that private copy as one file under an exclusive lock: a side file next to it at SQLite's first read refuses the import, and one that appears later is ignored. The integrity, required table and column, and timestamp checks run on that copy and only it is installed. A segmented import holds its staged hot database and segments to the validated digests before its restore journal is written, and SQLite side files next to the staged member still refuse the import. These refusals leave the current history unchanged.
