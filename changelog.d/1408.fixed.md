Restore: a failed import that is stopped while its rollback deletes the staged history copy no longer leaves a part-deleted copy under the name the restore record lists, so recovery returns the prior configuration and history instead of refusing; restore recovery now refuses a record whose phase, operation or kind fields are lists or objects with its usual explanation instead of an internal type error, and changes nothing; and a history database with a timestamp field longer than 256 bytes is now refused instead of installed, without truncating or dropping rows (direct history-database restore names the table and column; archive restore refuses the bundle's history member), while a failed import still returns a current history that already holds such a field; see #1273, #1287 and #1292.
