A pull request now records its changelog entry as one file named for its own
number, `changelog.d/<N>.<section>.md`, instead of editing `CHANGELOG.md`, so
open pull requests no longer conflict there. `scripts/changelog_fragments.py
collect` writes the entries into `CHANGELOG.md` when a release is prepared,
appending `(#N)` from each file name, and the release tools read the fragments
for unreleased work. The gate refuses a fragment named for another pull
request, and any change to a fragment already on `main` unless a maintainer
applies `changelog-edit-ok`.
