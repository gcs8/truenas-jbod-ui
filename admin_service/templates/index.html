    Backup

    Backup and restore

    Everything this app knows (settings, profiles, mappings, history) in one file. Encrypted backups are standard .7z files.

    What to include

      Choose what to include. Items with a lock contain passwords or keys and require an encrypted backup.

      Passphrases are used exactly as entered, including spaces in the middle or trailing padding. When encryption is on, export locks to a portable .7z bundle.

      You can export while the app is running.

      Debug Bundle

      For support

      Builds a temp-space support bundle from the current local stack. This exports a normal archive for offline inspection, not a standalone HTML and not an importable restore path.

        Secret scrubbing disables locked secret-path pills. Disk-identifier scrubbing keeps the bundle share-friendlier without changing the fact that this is still just an offline archive.

        Use this when you want a frozen local support snapshot without pretending it is the same thing as a restore-grade full backup.

        Restore

        No file selected

        Trailing spaces are preserved on import too, so padded passphrases round-trip cleanly. Import first inspects the archive and shows the observed encryption mode and aggregate counts for confirmation. Confirmation carries a short-lived, single-use inspection receipt bound to those exact archive bytes.

        Restoring replaces all current settings, mappings and history with the backup.

        Maintenance: use orphan cleanup after deleting or renaming a saved system when you want to remove leftover history rows that no longer belong to anything in `config.yaml`.

        This only removes history rows whose `system_id` no longer exists in the saved config.

        Renamed a system? Move its old history to the new name.

        Moves the history rows from the old name to the new one. Per-disk metrics already follow the disk.
